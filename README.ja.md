# Network Analyzer

*[Read this in English](README.md)*

ローカルネットワーク上のホストを検出し、ホスト名・MACアドレス/NICベンダー名・推定OS種別・開いているウェルノウンポートを一覧表示する macOS ネイティブアプリです。管理者権限やRaw Socketは一切使用せず、非特権のシステムコマンド(`arp`・`ndp`・`ping`・`ping6`)と `Network.framework` のみで動作します。SwiftUI + Swift Concurrency で実装されています。

## 主な機能

- **非特権のホスト検出**: sudoやRaw Socketは一切不要です
- **スキャン対象ネットワークの指定**: 開始IP・終了IP・ネットマスク(IPv4)またはプレフィックス長(IPv6)を指定して、任意の範囲を能動的にスキャンできます。起動時はこのMac自身のネットワーク情報に基づいた値が自動的にプリセットされ、いつでもワンクリックでその値に戻せます。IPv6の/64全体(2^64アドレス)を一度にスキャンすることは決してなく、範囲が広すぎる場合は黙って打ち切るのではなく、範囲を狭めるよう明示的に案内します
- **IPv4 / IPv6 タブ分離**: 「IPv4」「IPv6」がそれぞれ独立したタブになっており、スキャン結果・CSV出力もタブごとに完全に分かれています
- **NICベンダー検索**: MACアドレスからIEEE OUIレジストリを参照してメーカー名を表示します。アプリには初期データセットを同梱しており、設定画面の「ベンダーデータを更新」から最新の公式データを取得できます
- **ホスト名解決**: Bonjourサービススキャン・本物のマルチキャストDNS(mDNS)逆引きクエリ・通常の逆引きDNSを並行実行し、最初に成功した結果を採用します
- **OS種別の推定**: TTL値と開いているポートの傾向からWindows/macOS・Linux系/ネットワーク機器を推定します。常に「(推定)」と明記し、正確性を保証しない旨の免責文言を画面に表示します。これはあくまでヒューリスティックであり、フィンガープリンティング攻撃の類ではありません
- **ウェルノウンポートスキャン**: `Network.framework` で主要なTCP/UDPポートを確認します。UDPは「応答あり」「応答なし」のみを示し、Raw Socketが必要なICMP Port Unreachableの検出を前提とした「閉じている」という誤った判定はしません
- **結果テーブルのソート**: IP・ホスト名・MAC・ベンダー・OS・ポート・コメントいずれの列見出しをクリックしても昇順/降順で並べ替えできます
- **ホストごとのコメント**: 各ホストの行に自由な文言(例: 「リビングのスイッチ」)を直接入力できます。自動的に保存されCSV出力にも反映されます。コメントは再スキャンをまたいでは保持されますが、アプリを再起動すると初期化されます(仕様上、ディスクには一切書き込まれません)
- **CSV出力**: 各タブの現在の結果(入力したコメントを含む)をCSVファイルに保存できます
- **英語/日本語UI**: アプリはデフォルトで英語表示になり、画面上の言語ピッカーからいつでも日本語に切り替えられます
- **起動時は何もしない**: 「スキャン」を押すまでスキャンは開始されません

## 動作要件

- macOS 13 以降
- Xcode の Command Line Tools(`xcode-select --install`)があればビルド可能です。フル版の Xcode は不要です

## ビルド方法

```bash
cd NetworkAnalyzer-macOS
./build-app.sh
```

`dist/Network Analyzer.app` が生成されます(ad-hoc 署名済み)。

開発中に素早く動作確認したい場合は次のコマンドでも起動できます。

```bash
swift run
```

## 起動方法

```bash
open "dist/Network Analyzer.app"
```

常用する場合は `dist/Network Analyzer.app` を `/Applications` にコピーしてください。

## 使い方

1. 「IPv4」または「IPv6」タブを選択
2. 初回起動時、開始IP・終了IP・ネットマスク(IPv6タブではプレフィックス長)がこのMac自身のネットワークに基づいて自動入力されています。別の範囲をスキャンしたい場合は直接編集し、元に戻したい場合はリセットアイコンを押してください。入力欄の下には現在の範囲に含まれるアドレス数がリアルタイムで表示され、上限を超えると赤字になります。IPv6タブのプリセットは検出された/64全体で、これは常にスキャンするには広すぎます — 詳しくは下記「IPv6のスキャン範囲について」を参照してください
3. 「スキャン」を押してそのネットワーク上のホストを検出
4. 列見出しをクリックするとその列でソート(再クリックで昇順/降順を反転)
5. ホストの「コメント」欄をクリックしてメモを入力すると、その場で自動保存されます
6. 「CSVに出力」で現在の結果(コメントを含む)を保存
7. 設定(歯車アイコン)からIEEE OUIレジストリの最新ベンダーデータを取得

## IPv6のスキャン範囲について

/64サブネット全体には2^64アドレスあり、IPv4のデフォルト/24プリセット(254アドレス)のように「サブネット全体」を一度にスキャンすることは、このアプリに限らずどのツールでも実質不可能です。プリセットされた/64全体をそのままスキャンしようとすると、必ず「範囲が広すぎます」という結果になります。

また、IPv6アドレスはIPv4のように連番(DHCPの`.1`、`.2`、`.3`...のような)で割り当てられるとは限らないため、「これが正解」と言える範囲もありません。実際には、開始IP・終了IPを、実在する可能性のあるホストをカバーできる程度、最大4,096件程度に狭めて指定してください:

- **既に生存を確認しているアドレスの周辺で、最後のグループだけを変える**(例: `2001:db8:1234:5678::1` 〜 `2001:db8:1234:5678::1000`)
- **手動でIPv6アドレスを割り当てているネットワークの場合は、その割り当て範囲を対象にする**(SLAAC/プライバシーアドレスではなく)
- それ以外の場合は、ネットワーク全体を大まかに把握するにはIPv6タブの受動的な検出(NDP近隣キャッシュの読み取り)を使い、具体的で狭い対象が定まってから能動的な範囲スキャンを使うのが実用的です

この案内はIPv6タブの範囲入力欄の下に、リアルタイムのアドレス数表示とあわせて常に表示されています。

## テスト

主要ロジック(ARP/NDPのパース、ベンダーCSVのパース、OS推定、IPソート順、CSVエスケープなど)は`NetworkAnalyzerCore`ライブラリに分離されており、XCTestで単体テストできます。

```bash
swift test
```

※ `swift test`はXCTest.frameworkを含む**フル版のXcode**が必要です。Command Line Toolsのみの環境では実行できません(アプリ自体のビルド・実行にはフル版Xcodeは不要です)。

## 技術的なメモ

- どの段階でもsudoやRaw Socketは使用していません。ホスト検出はシステムの`arp`/`ndp`/`ping`/`ping6`コマンドを呼び出す方式で(MultiPingMonitor-macOSと同じ非特権の前例)、ポートスキャン・ホスト名解決には`Network.framework`と`dns_sd`を使用しています
- `arp`/`ndp`は必ず`-n`(数値表示のみ、ホスト名解決なし)付きで実行しています。`-n`なしの`ndp -a`は実際のネットワークで1回あたり30秒以上かかることが判明しました。これは、PTRレコードのない近隣キャッシュエントリごとに逆引きDNSを試みてブロックするためです
- スキャンは指定範囲内の全アドレスに実際にping(IPv6は ping6)を送って能動的に行います(同時実行数は4096アドレスを上限とし、`ping`/`ping6`プロセスが一度に大量発生しないよう制御しています)。その後1回`arp -a`/`ndp -a`を読み取ってMACアドレスを補完し、実際に応答があったアドレスのみを表示します。ほとんど使われていない範囲をスキャンしても、空欄だらけの行が大量に出ることはありません
- IPv6タブのプリセット範囲は検出された/64全体(約1.8×10^19アドレス)です。これをそのままスキャンすると必ず上限4096件に達し、範囲を狭めるようエラーで案内されます。IPv4の/24サイズのデフォルトはそのまま上限内に収まるのに対し、/64全体を能動的に走査するのは現実的ではないためです。詳しくは上記「IPv6のスキャン範囲について」を参照してください
- コメントはタブごとにメモリ上でIPアドレスをキーとして保持され、スキャンのたびに検出結果へ再度マージされます。ホストに関する情報の中で唯一、再スキャンしても「再検出」されるのではなく保持され続けるのがコメントです。ただし意図的にディスクには保存していないため、アプリを終了・再起動すると常にまっさらな状態から始まります
- OS種別列は常に推定値です。ICMPのTTL値(最も近い一般的な初期値である64/128/255に切り上げ)と開いているポートの傾向を組み合わせて算出しており、断定的な表示は一切行いません
- macOSでは`getnameinfo()`単体の逆引きDNSは通常のLANサブネットに対してmDNSまで到達しません(自動的にmDNSResponder経由になるのは`169.254.0.0/16`とIPv6リンクローカルのみ)。そのためホスト名解決では本物のマルチキャストPTRクエリも実行しています
- App Sandboxは有効化していません(本プロジェクトの ad-hoc・直接配布のビルド方式に合わせています)。署名時にはネットワーククライアントの Entitlement のみを付与しています
